# 新协议原生资格检查

状态：in progress（方案与隔离工具准备）。本轮承接[离线兼容定位](v3-compatibility-probe.md)，只检查当前参考模型能否直接生成新协议合格候选，不修改生产协议、提示词、默认服务、UI或保存格式。当前清单仍8/19；5.5研究0人、5.6真实完整联调未开始。旧模型对照No-Go和原生拒绝证据保持原样。

## 范围与责任

- 固定来源为组织者默认`bailian/deepseek-v4-pro-0813`、revision3，执行前核验实际账户、默认来源与可信路由；不取出或展示Key，不投射另一个型号，不改费用/额度规则。
- 固定7个独立的已知合成context，最多6次模型调用和1个零调用停止检查。这是样本数，不是新的会话次数或费用上限。**不是连续、自适应对话、盲测、真人体验或5.6验收。**
- 材料来自既有`RELATION_K_FULL`四段已知原句，额外交流要求与情绪澄清逐项固定。仅当前槽材料进入模型，无未来输入、模型回包seed、历史claim或伪造问答。自然输入同UI使用`kind=expression`，不把情绪澄清冒称真实前一轮模型曾说过“委屈”。
- Host使用实际v3 working state与`beginClarityRequest`派生stage/policy；真正API走`flow=clarity-v3`与`ai/clarity-v3.mjs`公共七字段契约。旧三字段compiler、E示例和私有hook不参与。不向模型附加评分答案、兼容映射候选或实验提示词。
- 模型负责生成原生候选；Host负责权限/形状/来源及状态应用；逐句语义另审，格式通过不认证忠实、拆解或陪伴价值。本人理解、许可、改善及保存意愿不由模型或程序测试代答。

## 固定槽与必过门槛

| 槽 | 当前材料与操作 | 结构及语义要求 |
| --- | --- | --- |
| listen | FULL首段＋只想说说/不用分析/不用追问 | 具体承接已说细节；question=null、finish=false，无分析/行动claim；reply也不读心、推断第三方或催行动 |
| continue | 前槽同样材料前缀＋FULL第二段，独立准备 | 保留早先禁问/禁分析，不因补充新材料解禁；不自动成稿；次数、各半小时、学日语时间被占/未补上不被改写 |
| clarify | FULL四段＋“请帮我理清。” | reflect/finish=false；允许有依据的理解，实际理解须连起想留住学日语时间与怕拒绝后见面尴尬，不能用愿意参与/希望先问替代；不重复索要已给的期待 |
| review | FULL四段＋“请AI整理成一份。” | review/finish=true/question=null；实际理解及呈现主文保留上述两侧关系；事实限定、临时先问/没空找办法、不是退出和尚未谈过不被改变；未知不变成第三方动机定论，不强填unknown块或行动 |
| correction | FULL四段＋理清要求＋“我不是委屈，主要是生气。” | reflect/finish=false；采用新肯定情绪，不将被否认情绪当当前感受；未撤回的日语时间/怕尴尬继续保持；不把自然澄清当撤回原顾虑 |
| corrected_review | FULL四段＋相同情绪澄清＋成稿请求 | 同review，另检查情绪修订；原生JSON与校验后的实际候选分别判定，不靠Host归一化证明模型自己采纳纠正 |
| stop | FULL首段＋“先到这里，不保存。” | 实际策略识别end/discard，begin拒绝`local_control_required`，无模型/计费/保存；只验证本地生成阻断，不证明UI清理或在途取消 |

每槽结果单列原生形状、原生忠实度、实际候选/主文与具体承接。FULL两侧关系、事实限定或否定失败独立No-Go，不能用其他通过项平均掉；没有足够理解内容也不算完成拆解。温馨/被听见需本人反馈，本轮只可判断承接是否具体、是否存在无据解释或催促。
