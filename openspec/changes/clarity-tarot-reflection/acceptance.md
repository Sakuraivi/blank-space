# 设计与实现验收

状态：r4 聚焦拆解陪伴，删除塔罗相关验收项；保留“具体承接、分析推进、连贯交流”的独立检查。核心切片及部分真实评估已执行，整体尚未达发布门槛，详见 [implementation-review.md](implementation-review.md)。内容价值、陪伴表达和交互轻松程度分别验收；样本是虚构材料，用户无需另行提供案例。

## 1. 内容价值门槛

困扰、选择样本按五项评分，每项 0/1/2：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 紧扣目标 | 泛泛共情或另起话题 | 有关联但重点不明 | 直接帮助当前一个问题 |
| 有意义的拆解 | 一段复述 | 有分类但没有区分 | 分清经历/解释、期待/未知或选项/代价 |
| 认知增量 | 原话润色 | 有提示但不具体 | 有来源的具体区分、取舍、修正或信息缺口 |
| 提问有效性 | 重复、带诱导或同时问很多 | 有用但可更聚焦 | 一个问题补一个关键缺口，回答会改变整理 |
| 成品可用性 | 看完仍不知理清了什么 | 能回顾事件 | 关键认识可复述、未知清楚、可选步骤具体 |

拟定发布门槛：每个核心样本至少 8/10，且没有单项 0；这是项目质量标准，不是临床量表或行业统计。任何虚构事件、确定性读心/预言、忽略用户纠正、未请求的高压建议均直接失败，不以总分抵消。

片刻样本不评“必须有新洞察”：检查具体细节忠实、意义得到用户认可、没有强造问题、没有模板场景扩写。允许仅保留一句原话。材料不足和提前结束样本以诚实留白为成功，不强凑完整度。

### 具体陪伴与分析推进（独立必过）

- 至少一轮承接用户具体投入或影响；把事件名替换后就可套到任何人的安慰句不能算通过。C01 例如回应专门留出的两个周六，而非只说“我理解你的感受”。
- C01 能追踪理解变化：从猜测不被重视，到分清取消与未重约，再看见想开口又怕催促，最后说清具体安排期待。每轮的回答确实改变下一问或成品。
- 感受或解释没有依据时明确保留不确定；用户否认后采用纠正。不能为了温暖自动站队、判定对方恶意或给关系下结论。
- 成品连起必要经历、原有顾虑与本次区分；三块抽象标签下的常识句不能算有深度。温暖不能只靠背景色、插画或结束语。
- 不强制每次回应都完整走“共情—分析—提问”模板，不重复同一种句式；开心片刻仍允许轻轻留住。
- 一眼能分清引用的用户原话与 AI 的候选理解，不让装饰或仪式感代替解释。

新版体验结束后除“理清了什么”，再问一次可选开放问题：“哪一句让你觉得被听见了，哪一句又不太像你？”记录具体句子；不能用满意度或设计师自评代替真实陪伴感反馈。

### 关键材料保留切片

使用 `ai/fixtures/clarity-retention-samples.mjs` 的朋友、工作、家人、兴趣活动四条合成链路，并加明确纠正与只留一句对照。分别检查最终模型候选与合并、保存读回后的可见正文：必要投入或代价、同时顾虑、具体期待及尚未知的解释是否保留；至少有一句说明从原先担心到现在分清了什么。引用了投入所在来源ID、但正文遗漏投入，仍判失败。

完整原句、状态合并及保存可用定向测试验证；顾虑改写是否忠实、区分是否有用、陪伴是否具体仍需人工逐项评审。关键词、字数或模型自评分不代替语义验收。新增切片不代替本节原有全样本、选择路径或首次无指导体验门槛。

## 3. 新功能定向行为验证

- 正常发送一次只记一个请求；快速双击不重复占用额度。
- 确认、回看、编辑、排版的调用增量均为 0。
- 解释暂不确定时，最终稿保留不确定性或排除；一次总确认也不能把第三方动机猜测升级为事实。未展示的新推断不能藏在详情后通过确认。
- 删除全部内容后能恢复；返回修改、断网、失败、切服务和晚响应都不丢手动修改。
- 已确认内容和用户修订不会被模型静默替换；上游变化能标示受影响内容。
- 最后一次调用后仍可编辑与导出；模型失败不触发自动重试。
- 不支持/无效 flow、错误来源版本、超限请求在模型调用前拒绝。
- 默认与个人 Key 路由及额度边界保持；不在日志或成品中出现 Key、提示词和原始会话。
- 旧记录仍能查看、编辑、导出；主文/详情分组不得改写原记录。后台管理认证和口令轮换不受此版本回退破坏。
- 首页无必选模式/主题，问答无默认侧栏和逐条确认；每个常规状态最多一个高强调动作。
- 足够材料后直接给短整理，确认与本机保存一次完成；失败保留草稿且不报成功。
- 发送时当前问题与答案绑定正确，返回查看不丢失回答草稿。
- 提前整理只能使用已经获得的回答，不能误用固定脚本后续内容。

依照用户“跳过回归验证”的要求，不执行旧版全量套件；新增定向测试、构建、静态校验、关键界面检查仍需要完成。跳过的检查应在交付说明中列明。

## 4. 视觉与体验检查

在桌面、390px 手机宽度及 200% 字号放大下检查：一个当前问题、无横向溢出、输入与主按钮不被软键盘遮挡、按键可触达、焦点清楚、减少动态生效。手机有滚动不构成失败，缩字凑首屏才构成失败。成品检查标题与正文左边线一致、节间统一、空节隐藏、长句换行、导出图无截断。

以下是项目设计预算，不是普适阈值，超过时先审查是否必要而不是机械截断：

| 项目 | r4 目标 |
| --- | --- |
| 字体与字号 | 叙事麦圆体400与常规控件字体分工；24px 页面标题、19px 当前问题/正文/输入/主按钮、14px 节标签与必要辅助说明；重要操作不使用小字 |
| 首页系统文案 | 一个问题 + 一句首次发送说明，不含用户输入 |
| 普通 AI 当前回复 | 困扰回应与问题通常约 70–140 汉字，可更短；以具体承接和推进为依据，不机械截断 |
| 默认成品 | 最多三块，困扰通常约 220–360 汉字；不设最低字数，关键经历与感受不能全部折叠，未知保持可见 |
| 高强调动作 | 每屏至多一个，位置稳定，名字就是实际动作 |
| A 样例主要提交 | 开始聊聊、三次发送、确认并保存，共五次；不强制走满，额外一问必须有作用；无必经选模式/认可理解 |
| 深层功能 | 提前整理、历史、编辑可发现；配置与导出不占主线 |

### 无口头指导的首次体验

建议先邀请 5 名未使用新版的人，仅给任务“用一件真实小事试试这个页面”，不解释界面，不提前教哪个按钮。以下为小规模发现问题的项目门槛，不是统计代表性结论：

1. 首屏观察约 5 秒，能指出从哪里开始。记录找错入口和犹豫的原因，不用询问其是否喜欢配色替代任务表现。
2. 至少 4 人无需操作指路即可开始、继续并保存；“下一步点哪里”的口头帮助单独记一次卡点。
3. 记录每次明显停顿、误点、反复阅读、寻找返回和放弃；用观察记录定位具体屏幕，不能只记“好麻烦”。
4. 结束后请用户用自己的话说“这次留下了什么”，判断简化后是否仍有一个具体认识；片刻记录不强求洞察。
5. 让用户找一次“修改”和“先整理”，确保按需展开没有让关键恢复能力消失。

这些测试尚未执行。设计师走通和固定脚本截图不能证明首次用户已经觉得好用。

首轮朋友体验后，入口旁只问一个可选问题：“这次有没有哪一点，比开始时更清楚了？”回答可选“有一点 / 还没有 / 只想留个记录”。再允许自愿补一句具体变化。它是用户自述，不是疗效结论；不使用体验前后心理分数制造效果感。
