### 当前字体：圆润的日记感（2026-11-01）

用户试读后认为文楷仍偏细、尖锐，希望更粗、更可爱的日记字体。本次选择[荆南麦圆体](https://github.com/maoken-fonts/KNMaiyuan)替代文楷：原生Regular400、笔画等粗、收笔圆润、带少量手写倾斜。字体本身已饱满，不额外伪加粗。具体字体感受是设计选择，仍需用户试读。

叙事、原话、提问、输入、记录标题和PNG使用麦圆体；功能控件与长历史沿用system-ui。继续使用24/19/14px三档、现有行距/纸面配色/交互。本节覆盖下文2026-10-31的文楷选型；历史验证记录保留，不能作为麦圆版的新验证证据。

### 用户反馈复盘

用户提供了五条原话，未提供样本人数、发生页面或操作录像。因此下面是结合旧界面与 r1 设计的可检验判断，不把它们当作统计结果。

| 反馈 | 设计判断 | r2 的处理 |
| --- | --- | --- |
| “这咋弄啊我有点看不懂” | 入口先要求理解产品和模式，没有直接带到表达 | 首页直接写一句，不先选主题、服务或整理方式 |
| “好多小字” | 辅助说明与正文同时争夺注意力；字号又弱化可读性 | 删除重复说明，正文 19px，辅助说明最低 14px；不能靠缩字塞内容 |
| “一瞬间不知道该按什么” | 多个相近按钮和可点区域同级出现 | 每屏至多一个高强调动作，名称直接说明结果，位置稳定 |
| “字体内容太多” | 多种字体/层级，加上重复回应、标签和长报告 | 一套叙事字体与常规控件字体、三档字号；默认只展示当前问题及必要内容 |
| “好麻烦” | 用户承担分类、抽卡、确认理解、收尾和保存的多次决策 | 取消必选模式与逐条确认，确认和本机保存合成一个动作；其他功能按需展开 |

r1 自查发现仍有风险：四阶段导航、三条线索侧栏、三按钮理解确认、六节报告、独立确认与保存。它们在本版本中退出默认主线。保留后台的拆解和来源状态，不要求用户学习这些分类。

### r3 对照评估：保留气质，重排核心页面

用户进一步指出 r2 示例没有拆解和陪伴感，并要求评估 UI 是否需要大改。对照旧站截图、r1 成品和 r2 示意：旧版的粉米色与梅紫色可以保留；重复容器、小字和操作层级需要明显调整。r2 虽删去多余操作，却把上下文藏起、把 AI 压缩成题目、把成品压成三个抽象结论，容易变成冷淡问卷。

| 层面 | 改动程度 | 具体取舍 |
| --- | --- | --- |
| 品牌色与气质 | 小 | 保留纸色、梅紫与低饱和衬色；加强正文对比，不用低对比小字营造温柔 |
| 字体和按钮 | 小至中 | 叙事与功能字体分工、三档字号；问题回到正常正文尺度，用间距与颜色区分，避免每道题都像考试大标题 |
| 首页 | 中 | 直接表达；插画只作品牌点缀，不能把输入和开始按钮挤到下方；不恢复多个相似入口 |
| 对话页 | 大 | 从孤立问答页改成连续交流：相关原话摘录、具体回应、一个问题、输入；较早历史仍可回看 |
| 成品页 | 中至大 | 三段有因果联系的主文，只有关键认识获得衬色；不恢复六张等重卡片或大段鸡汤 |
| 塔罗 | 本期移除 | r4 依据用户决定删除入口与相关状态，核心链路验证后再单独设计 |

推荐保留暖色身份、重做内容层次。仅换配色或加插画不足以解决问题；彻底换成星空、星座符号、大牌阵也会增加陌生感。以上是对现有材料的设计判断，尚无新版用户验证。

### 本地实现的视觉纠偏（2026-10-31）

用户在真实预览中指出“取消/确认位置不协调”和“没有第一版温馨的感觉”。这是对原定“保留气质”的落实，不是更换交互方向。本轮先修正视觉，再继续内容评估。

- 核心色恢复第一版：粉米底 `#F7EDE6`、奶油纸 `#FFFAF3`、梅紫 `#633B5C`、深紫正文 `#3E2F3D`、杏桃 `#F5DBC8`、浅丁香 `#E7DBE7`。
- 字体仍为一套中文无衬线，24/18/14px三档并支持放大。温暖来自窗边小屋、原品牌标识、纸面颜色与间距，不靠低对比小字和额外说明。
- 首页在同一纸面顶部用短标题搭配原有小屋，下面直接输入；手机标题按“最近，/有什么想聊的？”分行。对话与成品以左对齐正文为主，不添装饰侧栏。
- 布局：`[标题｜小屋] → [一句输入引导 / 输入框] → [发送说明 / 唯一主按钮]`。这延续原有插画身份，避免把简化后的页面做成通用空白表单。
- 确认弹窗限定较窄宽度，正常字号下两个操作等宽等高同排；大字号空间不足时一起变为全宽上下排。操作名说明结果：“继续聊聊 / 结束本次”“保留记录 / 删除记录”，不使用孤立的裸文字“取消”与另一整行主按钮。

### 文字呈现调整（2026-10-31，当前覆盖前述字体方案）

用户真实试用反馈字体锐利、不温馨。本轮保留纸面、插画、配色和交互，只调整文字角色。参考 [网易云音乐官方署名的2024年报发布与原图](https://www.digitaling.com/articles/1302797.html)：从原图观察叙事短段与操作入口的不同层次、留白及停顿，不据此认定其确切字体，也不照搬年报的大量分屏。

- 短回应、原话、问题、输入、三段整理与记录标题使用自托管 LXGW WenKai Regular 400；按钮、设置、说明与长历史使用 system-ui。不是全站更换成装饰手写体。字体选择是留白自身的设计判断。
- 三档基础字号更新为24/19/14px；回应/成品正文1.95行高，问题1.8行高，删除问题的600粗黑与字体合成加粗。语义标题不变，不额外添加提示文案。
- 使用 `lxgw-wenkai-webfont@1.7.0`（上游字体v1.250）原样Regular切片，97个WOFF2共4,634,808 bytes，按unicode-range加载，font-display:swap；不调用外部CDN。保留OFL与MIT许可及来源摘要。普通Regular替代Screen版，避免Screen官方已提示的macOS模糊风险；真实macOS/手机渲染仍待验。
- PNG导出先限时等待当前文字所需字体，度量和绘制共用同一字体；字体失败或等待超过2.5秒时使用常规字体，保留导出能力。
- 本轮是字体可读性的本地增量，不代表内容质量或新用户易用性验收完成。具体证据记录在implementation-review.md的最新条目。

采用“一次一个问题、一个主动作、次要功能按需展开”的交互方向；参考 [GOV.UK 的按钮层级](https://design-system.service.gov.uk/components/button/) 和 [NN/g 的渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/)。字号、字数和操作目标是本项目待验证的设计标准，不是通用科学定律。

已核实的工程边界：主分支 `ce9c2f2`；`ai/contract.mjs` 仅有 reflection / hypothesis / question / nextStep，最多三次追问；`public/core.mjs` 将其平铺为三段记录。当前状态不表达目标、解释和未知之间的关系。`ai/ledger.mjs` 单会话上限为五次调用；供应商输出上限因路由而异，不能假定都允许 2000 tokens。请求体边界为 12000 bytes。编辑与删除恢复已有实现，需要继承。主工作区未提交的 warmth 策略保持原状。

## Goals / Non-Goals

**Goals:**

- 一次体验围绕一件事，让用户辨认出至少一个具体的区分、取舍、资源或待验证事项；留下可再次阅读的整理。
- 降低表达负担：默认一问一答，随时能改、跳过、停下。完整度由当前问题决定。
- 将“温馨”体现在具体承接、尊重表达、清晰反馈和舒适阅读。
- 使每个成品结论能追溯到用户表达或明确确认；保留尚未知晓的部分。

**Non-Goals:**

- 读取未表达的思想，诊断人格/疾病，预测关系走向，替用户判断他人内心。
- 本期提供塔罗、抽卡、牌面视角或相关隐藏入口；连续打卡与心理评分也不在范围内。
- 把一件开心小事强行解释成矛盾、创伤或改善任务；给每次整理虚构“深刻洞见”。
- 调整现有共享预算或未经质量门槛直接发布版本。此前“仅做设计”的阶段已结束：用户“下一步”授权核心实现，并在本地页面配置了个人 Key 用于受控合成样本评估。

## Decisions

### 1. 产品核心：打开就能开始说

首页就是表达页：标题“最近，有什么想聊的？”，一个输入框，一个主按钮“开始聊聊”。取消 Hero 的进入按钮、三个主题入口和模式选择。用户不用先判断自己的事属于哪一类；系统从表达中选择候选场景，确实不明确时在对话里只问一个问题。

首次发送前保留一句可读说明：“发送后，AI 会读到你写的内容。”详细数据说明及个人 Key 入口进入设置。默认服务可用时不展示服务配置卡、厂商、模型、余额或预算。默认服务不可用则明确说明，提供“只记下来”作为主动作；个人 Key 配置是设置中的可选路径，不能逼首次访客先理解配置。

成品总称“这次的整理”。“理清了什么”是内容质量目标，不能作为每次必然达成的 UI 承诺。若尚未理清，显示“目前的线索”。

### 2. 一条主线，三种适度深度

| 场景 | 最值得回答的问题 | 通常结束条件 | 成品重点 |
| --- | --- | --- | --- |
| 留住片刻 | 哪个细节值得留下，它为什么对我有意义 | 细节 + 用户认可的意义已经足够，允许仅留原话 | 片刻、值得留住的感觉/条件、想留下的一句话 |
| 理清困扰 | 哪些是经历、哪些是解释；真正卡在哪里 | 形成一个用户认可的区分，或识别必须向现实确认的信息 | 默认卡住的、分清的、问号；关键经过与感受留在主文 |
| 权衡选择 | 两边分别保留与牺牲什么；决定还缺什么 | 有个人标准及一个关键取舍/信息缺口；不要求当场决定 | 默认个人标准、关键取舍、缺失信息；选项对照按需展开 |

三种路径共享状态与修正机制，最终页面按内容组织。困扰是首个实现和质量验证的纵向切片；片刻与选择沿同一契约接入，不复用困扰的全部标题。

### 3. 主流程与每屏职责

```text
Write --> One question at a time --> Short review --> Confirm + save
               |                        |
          stop / review              edit / expand
```

这三个体验阶段不渲染成步骤导航，也不要求用户分别点击进入。不会显示固定“第 2/5 步”或“再答两题就完成”的承诺。页面顶部保留品牌、可回看历史的入口；不能用简单化为理由删掉返回和恢复能力。

**表达。** 首页直接输入，点击“开始聊聊”发出首个请求。正文不另加产品介绍、重复提示和示例按钮。需要开头帮助时才展开例句。退出前有未保存表达应保留或提示，不制造无提示丢失。

**聊一会。** 默认是单列连贯对话，不渲染目标栏、分类标签或线索侧栏。保留上一条与本问相关的原话摘录（通常 1–3 行，明确标为摘录，不改写成用户说过的话），下面是一段具体回应与一个问题，再接输入。较早历史进入“查看前文”；不是每轮都把刚说的话藏掉。桌面也不自动扩成双栏。必要时回应可分两短段，不能为了省字删掉从材料到问题的联系。

- 主按钮固定“发送”；次级收尾入口“先整理”保持可达。用户可直接回复“不知道”或说明不想回答，不另设求助或换角度按钮。
- 不再每轮出现“贴近 / 改一下 / 暂不确定”三按钮组。用户可以直接在回复中纠正，也可在“查看前文”或最终稿里修改。严重歧义使用下一次问题澄清，不擅自当作已经理解。
- 有价值的区分融入一句回应，例如“还没重约是已知的；她是否不想见你，暂时还不能确定。”不另建三个解释框。
- 系统认可材料足够时，在本次回复下直接给短整理，不再加一个“看看整理”的必点页面。主动作变为“确认并保存”，并提供“再聊一句”；切换发生在回复完成后，不在用户输入中途更换按钮。
- 关键语义仍在模型和应用中处理。未保存前是候选草稿；用户最后的一次确认表示符合自己的表达，不等于外部事实已核验。

**短整理与保存。** 默认两到三个内容块，先看最有用的认识，再看在意/未知。按钮“确认并保存”一次完成内容确认与本机保存；不再先“留下”再“保存”。用户主动点“修改”才出现编辑、移除、恢复控件。保留在主文的模型推断必须出现在这个可读预览里，不能把它藏在折叠详情后由用户盲签；无依据的断言不能通过用户点击变成事实。

本机写入成功才显示“已保存在这台设备”；写入失败保持草稿与修改，明确提供重试。保存完成就可结束，不强推下一项任务。导出放在“导出”二级选项；生成话术或小尝试放在“继续整理”里，由用户主动选择。详细示例留在帮助区，不占据首页主线。样例必须标明虚构，复用相同成品渲染器。

**主线操作预算。** 朋友取消的修订脚本为：开始聊聊 → 发送具体经过 → 发送最介意的部分 → 发送具体期待 → 确认并保存，共五次主要提交、四次模型调用。比 r2 多一次有明确作用的追问，补上“愿意见面但怕开口像催促”的矛盾。若材料一开始已经齐全则跳过，不把五次当最低流程。输入字数与思考时间单独统计，不能靠少点击假装轻松。

### 4. 提问机制：先找缺口，再选表达

每个问题需要内部 `target`：补齐事件 / 区分解释 / 找到在意 / 比较取舍 / 确认未知 / 选择小步。它还需要当前用户材料依据和预期补充的槽位。缺口已经回答则不再次问同义问题；用户纠正优先于向下一阶段推进。

优先次序：理解错误 → 关键事实不足 → 混合了观察与推断 → 目标相关的需要或取舍 → 现实中才能确认的信息 → 用户主动希望的下一步。不是六道必答题。

本轮只增加 1–3 条有用候选线索，状态层保留、页面不逐条铺开。困扰对话的回应与问题合计通常 70–140 汉字，按实际作用决定；允许更短，不设硬上限剪掉关键联系。通常 2–3 个有效追问内提供收尾机会；不是固定问卷。用户疲惫或不想回答时立即允许结束。

**每轮如何同时有深度和温度。** 根据本轮材料选用三种作用，不要求机械填三句话：接住具体投入/影响；提出一个可修正的区分或张力；用一个问题验证或向前推进。朋友案例的进展是“实际互动 → 计划落空与没有后续的区别 → 想表达又怕催促 → 具体期待及未知”。这是面向用户的简短解释，不展示模型内部思考链。温暖必须落在用户说过的细节上，例如为两次见面专门留出周六；不靠固定“我懂你”、夸赞勇敢或添加环境描写。未表达的感受用“可能 / 听起来”保留余地，不把假设写成用户已经认可。

如果把某次回应换到任意其他事件也成立，或用户回答后对理解没有任何影响，就应改写该轮；反过来，开心片刻不为满足“深度”强造心理冲突。最终认可仍由用户决定。

### 5. 本期范围收敛：先验证拆解与陪伴

根据用户明确决定，移除塔罗、“换个角度”、牌面文案、问题切换状态及相关模型字段，不保留隐藏入口。核心链路为直接表达、具体承接与追问、形成有依据的整理、修改并保存。拆解能力由用户材料、提问价值和成品质量支撑。

用户答不上来时，可以自然回复“不知道”，系统允许保留未知或提前整理；不再引入必须理解的新玩法。当前问题 ID、问题文本与用户回答仍然绑定，普通问答的修正和恢复能力继续保留。

塔罗作为后续独立设计议题：先完成困扰路径真实模型接入、内容评估与首次无指导体验，再判断是否有未解决的表达困难值得用牌面帮助。本期不设计未来牌库、提示词、字段或验收用例。

### 6. 成品设计：阅读页与工作草稿各司其职

底层仍可保留最多六块成品材料，但默认阅读只呈现两到三个有用内容块：

1. **让你卡住的**：用必要事实连接原来的解释与顾虑，解释为什么难以往前走；不重复完整流水账。
2. **这次分清了**：本次具体区分及用户说清的期待，回答“聊完有什么不同”；只突出这一处。
3. **还留着的问号**：需要现实信息的部分，以及尚未作出的决定；无内容则不显示。

必要的经过和感受进入主文，额外过程才放在“回看经过”。困扰成品通常 220–360 汉字，不设最低长度；片刻可以更短。短文也须让人看出材料与认识的联系，不能把“你的感受很重要”当作成果。模型的新解释、行动和会改变判断的限制不能悄悄藏在详情。需要较多内容时正常纵向滚动，不把“首屏”当作缩小字体的理由。

选择路径默认“我的标准 / 关键取舍 / 还缺的信息”，对照表在“展开选项”中；移动端纵向排列选项，不塞四列小字。片刻路径默认“这一刻 / 我想留下的”，不出现问题、修复和任务标题。用户另行请求的小步/话术是可选补充，不成为每份记录的必有字段。

**视觉方向：一张有人接话的纸。** 单列、左对齐，叙事文楷与功能常规字体分工。最近原话使用轻量淡粉引用，AI 回应直接排在纸面上，避免每一句都套气泡。问题用正常正文尺度和常规字重、梅紫色与留白；输入与唯一主按钮放在回应之后。成品共用同一左边线，只给“这次分清了”一块浅丁香色衬底；其余段落用间距分隔，不做三张等重卡片。桌面外框约 688px、有效阅读行宽约 560px；手机纸面左右 20px，文字不嵌套多层窄框。小灯只作品牌识别，用户表达是视觉中心。

### 7. 状态、模型和证据的责任边界

应用拥有 `express / exploring / reviewing / kept` 状态、请求版本、确认/排除/恢复和保存结果。模型只能提交候选内容和建议的下一问题，不能直接进入下一状态或标记完成。

会话包括用户原话事件、当前目标、类型化的候选线索、用户修订和确认事件、问题历史、草稿版本。线索种类至少区分 event / thought / feeling / need / option / tradeoff / unknown / insight / action。每条拥有来源 ID、派生类型和稳定 ID。这些是内部状态，不直接映射为九组界面标签。

模型提出对现有条目的替代时以 `supersedes` 表达，不能直接覆盖已确认或用户改写内容。用户回改上游材料后，相关候选变为“需要再看一下”；历史内容和当前手动编辑仍可恢复。不能因为 `evidenceIds` 存在就视为语义有依据；实现前需用完整示例检查事实增补、暗含判断和上下文遗漏。

采用增量候选响应而非每轮输出整份长报告：简短回应、最多三条线索提议、一个问题或收尾建议、可选行动。应用把候选合并到工作草稿；收尾时按场景模板排列已有内容，不再付费调用一次“总结模型”。新认识在本轮可见回应/预览中展示，允许在最后一次总确认时认可，不要求此前逐条确认。没有呈现给用户的新推断不得因主按钮点击自动进入成品。

**保存契约的具体选择：** 工作草稿与最终记录分离。新增本地记录 `formatVersion: 2`，保留现有标识/日期/场景，`review.blocks` 最多六块，限定为 `text` 或 `option-comparison`；增加应用拥有的主文/详情分组，默认主文最多三块。比较行保存选项名、吸引点、代价、未知的纯文本，禁止模型 HTML。默认导出与主文一致；完整细节须在导出选项明确选择，原始对话永不自动附带。旧 `review.sections` 通过只读适配进入 text 块，直到用户明确保存修改才写成 v2；不批量重写历史。六块是底层容量，不是 UI 六个必填区。

提示词分三层：平台长期边界 → 当前场景/阶段/本轮缺口与允许行为 → 明确标记为数据的用户材料。各厂商复用同一语义策略，适配器处理请求格式差异。结构校验、来源校验、版本校验和保存过滤由代码保证；语义忠实与提问价值通过样本评估，不声称系统提示词能保证一切。

### 8. 调用与失败设计

#### 原句摘录与明确纠正的边界

困扰收尾的event改为从用户材料选择完整原句，保留限定语、来源及原顺序；分析仍由insight/unknown承载。应用按句校验，不能靠合法的来源ID接受改写后的事实段。请求数据中的grounding包含原句和明确纠正，不扩大指令通道；公开七字段协议及已保存记录不变。为避免冗余输入，turnPlan不再重复携带完整materials/controls，原始statements仍完整保留。最终请求仍受既有字节上限约束。

仅识别句首完整的“不是某感受，是另一感受”表达，限定情绪词表；引用、第三人称或“当时…现在…”不自动判为纠正。候选引用了纠正来源后，可将完全匹配的否定对照句归一为新感受；不补证据。仍残留被否认的感受则拒绝候选，不自动付费重试。此规则是窄范围文字处理，不是通用情绪理解；真实语义、他人感受及分析正确性仍需要内容评估。原句摘录也不能证明事件的客观真实性或分析充分性。

#### 2026-11-01 增量：离线句级材料选择实验

`ai/experiments/clarity-materials.mjs`独立于生产导入图。Host在任何await之前复制已校验context，以固定JSON序列的SHA256绑定会话、修订、阶段、原文/kind、问题关联及已知claims状态；不可变索引记录原始UTF16范围，mID只在该snapshotId中有意义。它是当前工作材料身份，不是事实认证、理解结论或权限令牌；手改包装词也照原文保留，不无依据剥离成用户键入原话。

私有`liubai-material-selection-1`为九字段，event只接受anchorIds与supersedes，Host按原顺序取完整原句并派生evidenceIds；insight/unknown仍是带原句引用的模型候选。编译后重新执行现有公开校验，并精确检查claims没有被前缀重建、控制路由或归一悄悄改变。完整明确纠正可按既有groundingPlan同来源顺序映射到真实正向后缀，trace记录原始/投影范围；其他含最终被否认词的引用保守返回不支持，不能称为通用情绪理解。

实验保守排除任何历史已识别的独立record/stop控制，防止把早期“不分析”从输入删掉；没有可选材料时也不构造请求。此范围不是线上行为降级，原生产分流继续执行。旧wire没有locked字段，实际state/apply仍是编辑保护与晚响应的权威，不能仅用compiler的status判断锁。索引/trace只在工作内存和合成评估证据中使用，不进入目前承诺仅保存确认正文的用户记录或默认UI。

当前build/compile为异步函数，尚不能直接替换同步runCandidate契约。接入前须准备与快照绑定的同步适配层或验证异步扩展的生命周期，并处理私有九字段与公开七字段元数据归一；模型调用前完成输入容量检查，保留来源、计费、并发、取消及过期响应保护。受控实验的known concern前提不能从旧mode候选直接当成已验证场景，仍须单独验证场景变化。

8个新合成样例及39个原句、54份完整序列化请求只证明工程组装和输入容量；9个故意语义错误的合法引用对照仍可能通过编译。它们未用于此前三版提示词，但已参与本轮实现检查，不是盲测。真实模型遵循性、输出token容量及交流/成品的语义质量仍未评估，未通过前不接入生产或切换首页。

#### 2026-11-01 增量：收尾事实段的纠正检查

离线原句引用实验复现了原校验的分支漏洞：concern收尾event的精确摘录或前缀重建跳过`repeatsDenied`，能把已明确纠正的本人旧感受重新带回。`clarity-grounding-4`将既有检查统一放到每条claim处理之后，不增加词表或新的语义规则。嵌套引号的`outsideQuotes`同步采用与原句扫描一致的引号栈，保留第三方引号内的情绪与纠正原词，同时检查真正位于外引号之后的本人表达。

该修复只补齐已定义的窄范围文字校验，不声明能识别所有改写、同义感受或复杂撤回。原始表达不修改，不进行额外模型调用或自动付费修复。新的句级选择协议仍作为独立离线实验，未接入本次生产路径。

#### 2026-11-01 增量：首次原话记录在浏览器完成

当前纵向切片采用保守的应用路由：依据已回答问题及原话中的显式期待、停止要求选择event/interpretation/need或收尾。缺口问题使用短的已审阅问句，模型负责具体承接和候选内容，不得改成虚构场景二选一。明确说清的在意点可跳到期待；已有期待、拒答或明确停止可提前整理。规则只决定交流动作，不证明用户已经理清，更不证明第三方动机。它仍有表达覆盖局限，须记录未识别或过早收尾反例；不能宣称已实现通用语义理解。

继续使用 `/api/ai/generate`，新增独立 `flow: clarity-v2`，旧协议保持原行为；非法 flow 拒绝。复用 source/config/consent/defaultRevision 绑定、reservation、requestId 去重、并发和晚响应防护。

用户本机实测反馈五次会话门槛会中断体验，取消新版clarity-v2前后端的每会话调用硬上限；callCount仅记录尝试与生成稳定ID，不授权调用或判断费用。内容明确即可收尾，用户仍可继续补充或请求可选行动。共享预算仍由组织者配置，单次容量、来源、认证、去重与并发保护仍由服务端检查。网络失败不能仅因前端尝试累计而锁住页面，也不声称网络失败必定免费。回看、确认、编辑、收尾排版均为零调用。旧v1独立限制不由本轮改写。

真实实测发现仅靠要求模型逐字摘录会在正常表达的收尾触发ungrounded_event。当前应用可从完整用户材料构造事实摘录，引用实际来源，保留通过校验的分析与未知；以完整句为单位选择容量内的前缀，不裁剪半句，原始输入不改写。若首句就超过剩余成品容量，仍明确失败并保留本地整理路径，不虚构替代事实。字段非法或来源ID虚构依旧拒绝，不通过摘录流程补造缺失证据。

本机实测预览使用独立的稳定工作树和隐藏后台进程启动，不依赖交互执行会话存活；开发中的选择比较保留在单独分支。日志只记录固定错误原因和请求元数据，不记录真实表达或Key。启动时检查端口与状态，不关闭占用端口的未知进程。

供应商有较小输出上限，故禁止一次返回整份九类报告。新契约应覆盖最小路由输出容量的定向测试；请求超过字节边界时明确请用户缩短，绝不静默丢掉修正或上游证据，也不先预留计费额度。对于已达到会话上限的情形，仍可编辑并保存当前材料，提示“先把已经清楚的留下”，不得宣称问题已解决。

## Risks / Trade-offs

- [仍可能只有精致复述] → 以完整输入到成品的语义对照验收；困扰和选择须有具体认知增量。不能靠 UI 截图或 JSON 合法率宣称有效。
- [确认过多破坏轻松感] → 默认只在保存前总确认；对话中自然纠正，严重歧义用一个问题澄清。
- [删字后又变成空泛总结] → 保留可验证的区分、个人期待和未知；成品质量门槛不降。
- [功能藏得过深] → 回看、修改和提前结束仍可达；配置与导出不占据主线。用首次用户任务检验发现性。
- [小字被折叠后掩盖重要信息] → 首次发送说明、费用归属设置、未确定结论和保存失败不得隐藏或缩字。
- [用户纠正后模型重新带回错误] → 显式修订事件、候选替代和 stale 状态；针对纠正链路增加行为测试。
- [五次调用不够复杂事件] → 聚焦一个目标、允许保留未知和早停；此版不以增加无限轮数掩盖提问质量不足。
- [手工样例优于实际模型] → 样例标识为目标样本；上线前单独记录真实模型运行证据及失败，不将固定回复预览当效果评估。
