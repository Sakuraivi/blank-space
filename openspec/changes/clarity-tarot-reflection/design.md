## Goals / Non-Goals

**Goals:**

- 一句话即可开始，允许只说说、没有新认识、自主停止、不生成报告或不保存。
- 愿意梳理时，具体回应和至多一个有用问题帮助本人辨认目标、顾虑、条件及未知；纠正优先。
- 用户意愿、模型候选、本轮请求完成、整理可呈现、本人确认及保存成功分别定义。
- 保留来源、有限纠正、手改/确认保护、失败原文和可恢复记录；按层取证温馨、易用和内容价值。

**Non-Goals:**

- 塔罗、重决策升级、长期/跨设备记忆、打卡、心理评分和扩大为通用知识聊天。
- 前置选择倾诉/分析模式、逐轮认可按钮、大改字体配色，或为每次倾诉强造洞见和行动。
- 把规划当成实现或效果证据、在本地切片交付中直接部署/改线上组织者配置/迁移存储；r5开发及发布仍须各阶段新证据。

## Decisions

### 0A. policy3线上整理退化修复（2026-11-01）

用户实际点击“整理这次对话”只得到原话，说明前次以本地拼接代替生成的交付不满足主动梳理目标。本次将该按钮恢复为一次真实review请求，自然明确成稿同样派发；“只保留已有内容”才是独立本地零调用动作。禁止分析/明确只记原话保持本地，暂停和结束优先。普通reflect即使没有insight，主动整理仍须请求模型，不把不存在的理解块当成功。

策略升为`clarity-listening-3`，七字段/schema2/format2不变。允许梳理的review禁止模型event，Host单独保全完整原话，模型主文负责有依据的理解、在意或未决处；仅复述event在完整校验中拒绝。材料不足不强造洞察，unknown也不被称已理清。失败保留对话并显示“没能完成整理”、手动重试及本地保留入口，不自动降级为已生成报告，不自动重试。原policy2/raw/No-Go历史保留；线上个人试用授权继续，默认服务配置和视觉不改。

### 0. policy2后续修复：原话与候选理解

[原生资格检查](v3-native-qualification.md)发现明确梳理仍可能只返回event摘录，另有情绪否定句误拦。后续使用`clarity-listening-2`策略，七字段schema2不变并将策略版本绑定票据/响应。Host保全生活原话为可见、可删的独立source块；模型专注具体回应与有依据的候选理解，不把event/内部goal当已经给本人看见的拆解。event仅留工作态/trace不隐式确认，所有非event模型候选可见；缺理解如实表示，历史/手改记录中性呈现。确认时选择保留的原话可随记录写本机，默认仅导出主文，控制/问答/Key不保存。新增有限否定-肯定检查原样保留模型文字，旧v2纠正规则不改。详细契约、反例及尚未验证部分见[listening-2-repair.md](listening-2-repair.md)，不能用这次工程修复升级原内容No-Go。

### 1. 一条主线与用户控制的分支

```text
Express --> Respond --> Continue
               |          |
               +<---------+
               |
               +--> Explicit review request --> Candidate review --> Optional save
               |
               +--> Pause / explicit end without saving
```

首页保持直接输入和「开始聊聊」，每屏至多一个高强调动作。对话保留相关原话、短回应、可选问题与输入；没有问题时不渲染问题区，也不补「还有什么补充或纠正」来制造待答题。普通续说仍是expression，实际问题存在时才建立问题与后续表达的关联。

用户说「帮我理清」可以在对话里得到区分或一次有用澄清，不自动跳成品；只有明确要求形成整理或点击明确成稿动作才请求review。生成整理不表示对话必须结束，用户仍可修改或继续说。不存在固定轮数的完成承诺。

### 2. 意愿是Host派生策略，不是模型推断的权限

| 输入信号 | Host处理 | 不可自动推出 |
| --- | --- | --- |
| 明确只想说说/不用分析 | 保留倾听偏好，回应具体已说内容，禁止新增解释和建议 | 已经结束、必须记原话或保存 |
| 明确不要追问 | 禁止本轮及后续追问，直到本人明确改变要求 | 禁止一切整理、已经没话说 |
| 想理清/想一起想想 | 允许有来源的区分和必要的一问，持续保留未知 | 已经许可行动建议或生成完整报告 |
| 明确请AI整理成一份/点击成稿动作 | 本次review请求；只用已经表达的材料 | 已认可内容、已理清、已保存 |
| 暂停/取消等待 | 取消请求并使ticket失效，保留当前原文与草稿 | 上游出错或应该重试 |
| 明确结束且不保存 | 取消请求，按明确丢弃意愿清理本次工作内容 | 自动生成告别报告或永久保存对话 |

仅本人明确、非引语的交流要求及合法显式操作构成控制依据。引语、别人说的话、模糊心理解释不提升为权限。歧义时沿用较保守的权限、继续具体承接，不增加分类模型或必经模式问答。混合结束与其他含糊要求时先停止请求、保留内容，由本人选择后续动作，不自动丢弃或续费生成。

服务端从绑定的表达与合法操作重建策略；不接受模型写入意愿，不接受任意客户端allowQuestion/allowInterpretation等自由权限覆盖。策略随请求的context/profile/revision快照绑定，最新明确要求优先，变更使旧候选失效。单次成稿或行动仅授权该次要求范围，不默认解除先前的禁问/不分析偏好；本人明确要求一起分析时才相应更新。控制语句不当成生活经历写进记录。

阶段2A实现细化：未获明确梳理要求时，默认不授权新增解释或分析claim；忠实承接本人已明确说出的感受、顾虑仍可进行。明确一起理清才持续开放分析；单次review在没有显式分析禁令时可授权本次整理所需的分析，不改变后续对话的倾听偏好，也不解除禁问。控制识别仅覆盖有限、明确、非转述的语法，不冒称通用意图分类器。来源窗口12条、active claims 15条与可信路由字节、输出及本机记录容量分别检查；没有对话调用次数上限。

### 3. 显式新行为版本，保持旧契约可回放

r5使用 `flow=clarity-v3`，公共候选schema `liubai-clarity-2`；旧clarity-v2、旧四字段路径及其校验保持原语义。不得依据输出形状猜版本或让旧客户端静默接受新行为。候选仍为modeId/goal/reply/question/claims/finish/title七字段，公共schema版本与保存记录formatVersion是不同边界。下表普通交流/成稿与既有独立行动请求分开；行动只进入actionProposal，不开启或覆盖正文review。

| 请求阶段 | 新版本候选约束 | Host可执行结果 |
| --- | --- | --- |
| reflect | finish=false；question可null；有问题时仅一个且符合权限与来源；claims可空 | 短回应或可选一问，继续exploring |
| 本人明确请求的review | finish=true、question=null；至少一条有来源的候选内容 | 呈现可修改的review，不声明用户已清楚 |
| 主动可选行动 | 仅既有明确授权的action，沿用独立权限和来源检查 | 可采纳建议，不自动改正文或追加追问 |

模型的mode/goal、问答关联和finish都只是候选或生命周期信号，不是用户意愿或理解事实。question、显式分析claim和行动分别检查各自的当前权限，违反相应权限或阶段组合时拒绝，留原文、不重试；禁问不等于禁分析，本人可要求「可以一起分析，但别再问」。不能前端隐藏或补固定问句后记合规。reply内是否暗含无据解释、建议或假共情仍须人工对照，不能声称字段校验已证明语义正确。

不把每轮都生成完整报告作为容错策略。不把旧三字段review示例直接塞入新七字段对话协议；不同环节的模板、schema、版本和实际body分别核验。

### 4. 生命周期、本人反馈与存储分离

沿用express/exploring/reviewing/kept主要状态，但请求阶段不再由三次回答或出现期待自动切review。正常无问句回复保持exploring，候选review只表明草稿可呈现。未确认整理使用「目前的整理 / 一点可能的理解 / 还留着的问号」，缺块不补齐；不以模型finish自动显示「这次分清了」。

本人确认仅表示愿意保留这些表达，存储写入成功才表示已保存；不升级为第三方事实核验或本人情绪改善。被听见、轻松些、理清些来自本人自愿反馈，本切片不新增模型代答的体验评分或自动记录反馈接口。

主动暂停、上游失败、明确结束不保存分别呈现。暂停不使用红色「没收到可用回复」状态，不自动重试；实际已发请求仍照实记账。仅模糊离开需明确丢弃提示，已明确结束不保存不再强迫生成或留存。清理限本次未保存工作内容，不删除已确认保存的历史记录。意外离开前说明未保存内容边界，不借恢复能力偷偷永久保存原始对话或Key。

### 5. 调用、材料与兼容边界

- 每次有效表达至多一次生成；没有自动意图分类、总结、审校或失败补发。
- policy3中“整理这次对话”是明确成稿动作，派发一次review并独立记账；自然语句明确要求成稿同样属于一次用户触发请求。“只保留已有内容”及保存、编辑、回看、恢复、导出和结束为本地动作，零额外模型调用。policy2曾将唯一整理入口降为本地拼接，作为已发现退化保留记录，不继续作为当前设计。
- 12条原始表达、active claims容量、实际路由完整请求字节/输出容量及本地记录大小分别受检。r5问答关联允许覆盖该材料窗口内的实际回答，不保留三条的隐形上限，也不靠清空关联重置次数。
- 超过三次问答仍可继续；问题是否重复/已被拒答与是否有价值分别检查，不用固定三问或五次调用认定体验结束。无意义的问题不以Host固定句补回。
- 容量预检在新请求前完成，不抬可信路由上限、不静默裁掉早期来源。达到容量保留已输入内容，提供本地收尾与完整文字保留路径；保存受限或失败不显示已保存，仍可留在本页/下载文字。MVP不承诺无限长聊或自动跨段记忆。
- 继承真实问题/回答绑定、stale、晚响应丢弃、手改与确认块保护、删除恢复、幂等和账本。保留10秒慢提示、60秒完整请求截止；这些不是用户聊天轮数或开发测试总费用上限。
- 不改Key来源、组织者默认型号/revision、预算、口令、D1或DNS。r5保存继续兼容formatVersion2及新版storage key，不重写旧记录或旧key；flow名中的v3不要求存储迁移。

### 7. 内容与真人验证分别过关

1. 固定当前E示例条件、八个已知context和旧三字段协议做候选模型对照，仅改变模型；先核验账户权限、精确能力与隔离路由，默认配置不随比较变化。费用无总上限，固定批次只是实验长度；保留失败与实际usage。
2. 对照只作模型筛选，不认证新flow。核心FULL两侧关系、条件与否定范围必须通过；不以总分、引用合法或完整event抵消分析遗漏。无合格候选时给出失败与替代方案，不暗降为复述或无限叠提示词。
3. 入选模型与新Host切片联调，使用新材料和实际逐轮回答，不补固定未来输入。倾听、按需梳理、片刻及恢复分支各自取证。
4. 两人形成性研究可在原型/稳定入口上先发现节奏与措辞问题；脚本、回放、帮助均标注，只能支持对应范围结论。
5. 五人无指导验收使用未体验该版本的人，前二后三；形成性两人不抵数。核心成功为至少4/5自行开始、继续及选择收尾，保存/找回另作自愿功能证据，内容价值与本人感受不按保存率代替。

### 8. 视觉与当次价值

继续奶油纸、粉米、梅紫、小屋和麦圆体，不进行第二次换皮。24/19/14px分工继续，重要的停止、修改、整理动作采用可读正文尺度及可触达区域，14px只承载必要辅助信息。默认单列、左对齐、至多一个主动作；没有问题时减少页面负担，不补说明板。

倾诉者允许「话说出来了」即有当次价值；请求梳理者需要有材料支持的具体区分或未知；片刻只要忠实。本人觉得没帮助、仍没清楚或不想保存同样记录，不强制正向。反馈方法与项目门槛见acceptance及beta-test-kit，不新增心理量表或疗效承诺。

## Risks / Trade-offs

- [仅改提示词，状态仍逼问/结案] → 新版本联改契约、问答归类、阶段、schema与UI，覆盖所有三题假设。
- [将节奏全交模型] → Host握住来源、用户权限、请求和存储，模型只建议内容；语义价值仍由真实评审验证。
- [把倾听变成泛泛附和] → 具体承接原话，禁止无据归因、奉承和未请求建议；保留拆解场景的独立门槛。
- [新旧客户端或记录混用] → flow/schema显式分流，客户端核对响应身份；记录格式不随flow改名，回退不清理数据。
- [容量限制被伪装成已理清] → 先预检并保留全文，明确容量状态及本地选项，不裁原话或假保存。
- [方向研究替代正式验收] → 原型/辅助与真实版本分开，2人与5人不混计，主观体验不从模型分数推出。
