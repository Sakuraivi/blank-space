## Context

基线ff679f6。现有public/app.mjs的remove-section直接splice；review全部移除后只提示回首页。layout进度仅静态li，go会使AI请求失效但不先捕获编辑；enterReflection和makeDraft存在生成入口。requestAi的review成功分支见已有review便return，不能直接承担保留旧稿的重整。public/core.mjs的已保存结构最多6块，aiRequestSession显式过滤review和confirmed；动机见proposal。

## Goals / Non-Goals

**Goals:** 页内可恢复板块、保留编辑的步骤回看、可靠的旧稿未更新状态、显式重整及失败保护；只以新增smoke和本地模拟验证这条链路。

**Non-Goals:** 不加服务端草稿、自动保存、localStorage恢复、跨设备历史、无限板块、自动AI续聊或提醒。不改变模型提示词、授权字段、默认服务版本/付款来源、保存schema及既有凭据生命周期；不跑旧/全量回归。

## Decisions

1. 新增独立纯函数模块管理本稿稳定板块集合、可见状态、移除顺序和恢复。移除前先capture用户输入，保留板块id、text、label与source；撤销只恢复上次仍移除项，恢复全部按稳定原序，重复恢复幂等。选择可恢复集合而非破坏性splice，避免从原材料重建而丢失用户改写。DOM仍只显示当前可见项，恢复数据不放入已保存对象。
2. root已确认稳定集合active+removed总数最多6。补写只在集合有空位时建立一个用户来源的空板块；满6时提供恢复再编辑说明，不能偷偷清缓存或建立第7块。此决定避免新增板块与恢复全部冲突时再引入取舍弹窗。确认仍沿用标题/正文校验并过滤空正文，空稿必须给出可操作的恢复路径。
3. 由页内状态记录本次已到达步骤；实际到达、完成或显式跳过后可回看，未来按钮禁用，当前保留aria-current。导航统一先capture，再取消/失效当前请求，再展示目标；回到卡片保留已有卡片，回到问答展示本次已有回答。纯导航与既有“继续/生成”动作分离，不能通过enterReflection或nextQuestion隐式发出AI请求。
4. 每个成功整理稿记录源材料基线和所属reviewKind/reviewSources，导航本身及仅request revision变化不视为材料变化；故事、焦点、卡片/联想、回答、turns、纠正及可选建议授权等源内容变化后标记未更新。旧标题、可见编辑、移除缓存与来源均保留。此状态放在控制器内存，与会发送到模型的session快照和确认后记录隔离。
5. 重新整理是单独动作：AI方式先明确确认再次发送/可能计费及替换编辑；取消确认零请求。等待时旧稿仍存在，可返回旧稿且使新请求失效；失败/超时不重置旧稿。仅通过既有stillCurrent、route/defaultRevision、requestId/revision及候选/evidence验证的当前成功结果，可原子替换整理稿与源基线并建立新恢复集合。不能先置空review来绕开原有成功分支，也不能为接收重整结果放松迟到门禁。按原话重整也须显式动作后才替换旧编辑，导航不会代替该动作。
6. 复选框展示改为“在整理中附上一条可选的小建议”；辅助说明为“根据你分享的内容给出，想不想尝试由你决定；不会自动执行或创建提醒”。保留原checkbox id、allowNextStep布尔授权和模型可返回null的协议，勾选本身不发请求。

## Risks / Trade-offs

- 索引变动可能把编辑写入错误板块 → capture在每次导航/移除前执行，以稳定板块身份维护恢复关系，新增smoke覆盖连续移除、编辑与恢复顺序。
- 导航混入现有生成入口导致重复付费 → 为回看单独分发，只在明确继续/重整授权后生成；本地模拟以请求计数证明纯回看零增量。
- 保留旧稿时误接纳旧AI响应 → 保留所有现有请求失效与来源检查，新增慢响应返回旧稿场景；取消和失败前后比较旧稿快照。
- 已满6项时不能直接新增补写块 → 明确引导先恢复一段再编辑，保持恢复全部及历史schema可预测，不加入永久删除或隐藏丢稿行为。
- 本次跳过旧回归 → 只声明新增目标smoke、本地模拟和相关构建结果，不将旧测试数或真实模型质量当本次证据。

## Migration Plan

无需DB或保存记录迁移。模块owner实现页内纯函数和新增目标smoke，root接app导航/捕获/重整与建议措辞，样式owner只改相关CSS；按tasks顺序联调。验收采用虚构材料、假模型和临时页面内存，检查桌面/390px、恢复空稿、回看零请求及重整失败/迟到不丢稿。发布若获授权则沿用同Worker/D1；回退前保留用户自行导出的确认记录，不把未确认材料写入服务端或新增持久化来规避页内生命周期。
