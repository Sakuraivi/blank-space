## Context

现状及动机见proposal。当前目录同时承担默认计价、传输信任和个人模型选择，getRoute对象同一性又被transport使用。前端、ledger模型ID合法集不一致；全局safetyStopped把个人error也视作共享停用信号。

自有子域名仍指向Sites共享入口。现有公开权限已核验，但不能控制其边缘拦截规则。用户已同意独立托管至账户 `1420888f16c72742e6bde4cd995d156f`；旧Sites、独立候选和最终域名的执行边界须分别记录。

## Goals / Non-Goals

**Goals:** 四家统一个人模型选择、固定官方端点、统一规则/候选校验、保留原记录和同意锁定、默认预算与个人异常隔离；独立托管且在不重置账本的前提下切换域名。

**Non-Goals:** 实时模型发现、任意兼容供应商URL、保证任意模型ID可用、调整价格/有效期、真实账户推理测试、放宽默认共享模型、升级付费或保证所有网络可达。

## Decisions

- 默认getRoute保持封闭；服务端另签发personal route，使用进程内WeakSet验证对象身份，拒绝客户端伪造endpoint/profile。不用无界字符串缓存。
- 个人已预设模型可沿用已适配参数；未知模型使用generic Chat Completions文本协议、system场景规则和保守输出限制，不硬塞reasoning/thinking/cache/JSON格式可选参数。不兼容时受控失败，不换Key或来源。
- 模型ID统一为1–100位ASCII字母数字及`_./:-`，拒绝URLscheme、空白、控制字符与查询片段。日志只标记custom，不记录任意原始ID；账本为路由幂等保留合法ID。
- catalog逐provider声明allowCustomModels。findAiProfile默认严格，仅personal路径opt-in；defaultProfile仍必须来自已知目录。公开版本multi-flex-v1；consent版本不变。
- 自填模型使用personal-unpriced-v1标记，不进行共享价格估算或扣费预留。个人仍执行单次Token/字节上限，异常不影响默认持久熔断。默认费率、预算与历史保留。
- UI采用预设下拉与“填写其他模型ID”，只在选择后显示文本框；已有自定义配置可重开。切provider/model不复用旧Key，Key不回填DOM；首次story配置续接、提交锁定及离页清除维持原行为。
- 自管候选使用独立Worker与D1，不通过Sites反向代理；公开页面、静态资源及同源API不依赖 `chatgpt.site`。独立入口剥离外部伪造的 `oai-*` 身份，旧管理API一律拒绝，不能把Sites专用身份头当作公网认证。
- 候选初始为 `pending`，生成API在解析凭据、预留或出站前拒绝；只有冻结快照、全列摘要、共享统计、接口及权限核验均通过后才改为 `verified`。公开配置版本仍为 `multi-flex-v1`，不借迁移改变付费、同意或批次口径。
- 旧Sites维护至少阻止新的generate，同时停止配置管理写入；所有已分发请求须取得终态，在途归零后才形成最终快照。逐表记录全列、行数及规范化摘要，不以TTL排除或只对比剩余额度代替一致性证明；当前16次/¥0.80为已核验基线，最终以冻结快照为准。
- `pilot_config`、`pilot_requests` 等实际源表按全列迁移，不新建空账本补默认额度。秘密项另走运行时配置，不写入源码、快照报告或日志；浏览器本地记录不自动上传。
- 独立配置、入口和迁移核验步骤须纳入可复现的项目源码。现有 `work/liubai/standalone/` 草案仅供准备，不能单独作为可维护的正式交付。

## Risks / Trade-offs

- [合法ID不代表该账户可调用或协议兼容] → 不做自动付费探测，页面说明需支持文本聊天，错误保留原文。
- [自填ID误填私密内容] → 严格合法集、日志不记录原始自定义ID、不把Key放入候选上下文。
- [模型扩展被误认为网络拦截修复] → QA分别记录公开权限、匿名单点访问与测试者边缘错误，不承诺Sites跨网络可达。
- [新旧两端同时生成造成预算分叉] → 旧端持续维护；候选核验前关闭API；切换及回退均先冻结当前写入端并等待在途归零。
- [回退丢失候选新增消费] → 全列导出候选增量，按请求ID及幂等字段合并到旧账本，冲突即暂停，不覆盖旧行；配置差异也须核对，未核验前旧端不得恢复生成。
- [切换后其他网络仍有边缘或DNS问题] → 保留回退目标与测试记录；原受阻测试者成功加载页面、静态资源及状态API后才可宣称本次拦截修复，不能宣称全网保证。

## Migration Plan

1. 同包构建服务端和前端 `multi-flex-v1`；旧页面在生成前拒绝并要求重载。形成可复现独立部署配置与包摘要，候选绑定用户账户的独立D1并保持pending。
2. 发布旧Sites维护状态，停止新生成及配置写入；等全部已分发请求终态后记录源表清单、全列快照、行数、摘要及共享统计。无法证明在途归零即不继续。
3. 将最终快照导入独立D1，核对表结构、全列摘要、共享余量及历史请求归属；保留个人预留0、默认历史和错误记录，不改价格有效期。运行时秘密另行配置，不输出其值。
4. 验证pending拒生成、伪造身份及旧管理API被拒、公开页面和同源状态无Sites依赖；核验通过后才将候选设为verified并检查实际配置。过程不调用真实模型、不升级付费。
5. 最后将 `blank.sakura.observer` 路由切至自管Worker，旧Sites持续维护。记录切换前后目标与时间，并邀请原受阻网络测试者验收；成功前只报告迁移状态，不能报告拦截已修复。
6. 需回退时先冻结独立端并排空在途，再把新增账本和配置差异合并核验至旧端。可先回到旧冻结页面，但必须完成增量合并和源配置检查后才恢复其生成；不得直接恢复旧快照或同时开放两端。
